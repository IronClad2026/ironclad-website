# Ready platform capabilities on Staging

The integration uses the Staging Clerk session. A private request resolves the live player record for that Clerk identity and reads the caller’s registration rows with the existing Clerk-authenticated Supabase client. A closed or missing player profile yields public guidance only. The match table requires the existing server role. Ready queries both seats using the caller’s registered IDs and checks the tournament and Division against the owned registration. Public responses use the same event visibility rules as the Tournaments page.

| Request | Source and existing destination |
| --- | --- |
| Find or enter an event | The public tournament projection and `getTournamentRegistrationAvailability` supply dates and the live registration window. The caller’s registration status, profile completion and current account legal gate help explain known blockers. `/tournaments?tournament=<slug>&register=1` opens the existing workflow. It performs the authoritative eligibility, Steam/RELIC, consent, available Division and duplicate checks. |
| Find my match, opponent or deadline | The launched bracket, current seat registrations, match status, deadline and hold fields are read for the current account. Multiple matches produce choices. A missing assigned opponent or active match produces an explicit empty state. `/tournaments?tournament=<slug>&tab=brackets&match=<owned-id>` uses the existing match workspace on desktop and mobile. |
| Open opponent chat | The same focused match route opens the existing Match Room, under its own session and membership controls. An existing owned Assistance record can supply an immutable room ID for historical read-only navigation. Match reassignment, closure, unread state, and any new room created through normal navigation remain governed by the platform. Ready reads no transcripts and performs no chat operation while generating its answer. |
| Submit a result or upload replays | The focused match workspace contains the existing score and replay form. Ready gives access instructions and a link. The form controls current eligibility, required replay uploads and submission. |
| Contact an admin | The verified Discord ticket panel and separate server invitation remain available. For an active eligible match with both relevant Staging settings enabled, the match workspace offers its existing Admin Assistance controls. An existing requester-scoped conversation can be opened at `/assistance/<request-id>?tournament=<event-id>`. Ready can provide a copyable match reference. Opening a destination creates no support ticket. |
| Read applicable rules and decisions | The authoritative public rules hub and vetted document collection supply citations. A player’s `registration_acceptances` row selects the immutable versions for their chosen event. Ready checks each recorded hash against the approved delivery manifest. Unknown histories do not inherit the latest version. The selected tournament’s Rules, Prizes and Decisions panels expose event terms. A published Decisions link is confirmed through the existing public decision projection. |

The Staging settings check confirmed Match Room activity and creation of private Admin Assistance requests are enabled. The separate ELO verification control and the prior match-chat translation flag are disabled. The retired translation runtime and Cloudflare variables are documented in [Patch 2 translation cleanup](patch2-phase4-staging.md). Ready makes no requests to the email or push systems. The repository’s Staging side-effect controls continue to govern the existing workflows.

The configured ticket panel is recorded in `lib/support.ts` with the operator’s verification. It points to the [Discord ticket channel](https://discord.com/channels/1440092095619662105/1440201093110960137), where members use the panel’s ticket creation button. The public [IronClad About page](https://www.ironcladtournaments.com/about) links the separate [server invitation](https://discord.gg/ZQSQjBNRm3). Opening the Discord channel requires its normal sign-in and membership.

Staging’s four previously tested Academy review fixtures have launched match history and no current activated match. Use the designated accounts and their existing past matches for read-only browser checks. A new active test pairing can exercise the full active-match journey when available.
