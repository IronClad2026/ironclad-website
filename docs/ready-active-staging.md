## Run the fixture

1. Confirm the exact Staging project, that Vercel Preview / staging sets `TRANSACTIONAL_EMAIL_MODE=disabled`, and that push claims remain blocked. Record the UTC time of the fresh email check.
2. Review [the fixture setup](../tests/patch2-db/hosted-ready-active-fixtures.sql). Substitute the fresh run and email-verification times in memory for the two timestamp markers. Run the full transaction with its default `rollback`. A successful rehearsal returns `committed: false` with an empty durable manifest. The scope and existing data assertions run before the rollback.
3. After a passing rehearsal, use the same source, fresh timestamps, and replace only its transaction terminator with `commit`. Keep the returned nonsecret manifest under the ignored `test-results/ready-staging` evidence directory. The transaction suppresses generated deliveries for only the two new synthetic events.
4. Run `scripts/ready/staging-hosted.mjs` in the existing Vercel Development Trusted Sources environment with the exact Staging deployment URL, ID and SHA. Add `--active-fixture-manifest test-results/ready-staging/ready-active-fixture-manifest.json --headed`. The script uses temporary test sessions and revokes them. It reads Match Room history with actual participant tokens and checks that both histories and assistance remain empty. The desktop and touch-emulated browsers allow only the Ready request and the scoped native room lookup and context actions.
5. After verification, confirm the delivery guards again. Use [the fixture close transaction](../tests/patch2-db/close-ready-active-fixtures.sql) with the two exact manifest tournament IDs and a fresh email-verification time. Rehearse with rollback, then commit the single terminator change. Check that both rows show `cancelled`, their history is retained, and no fixture delivery is eligible.
