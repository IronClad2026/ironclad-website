# Ready on Staging

Ready uses the approved `cd0a72d` mascot artwork and renderer. The standalone mascot review remains the recovery copy. The existing conversation stays in browser memory and the trial writes no feedback, messages, assistance tickets, results, or registrations.

## Access and release

Deploy from the dedicated `codex/ready-staging` worktree through the established protected `staging` Git ref. Vercel binds the development Clerk instance and the Staging Supabase project to that ref. The server needs all of those boundaries and `READY_STAGING_REVIEW_ALIASES` set on **Preview / staging**. The initial reviewers are the existing synthetic TestAcademy1 and TestAcademy2 actors. Ready verifies backend fixture metadata, an unlocked Clerk account, an open player profile and current account legal acceptance. A request derives its identity from the live session. Without the setting, the page renders the regular header and the API declines the request. Signed-out players can read the public rules hub.

The live feature uses read-only lookups. Existing player actions link to the established tournament and Match Room interfaces. Opening a route can perform that interface’s normal read and initialization work. Users retain control over sending messages, requesting assistance and submitting results. The Staging email-disable setting and push-claim permission block remain in place.

## Optional free inference

Source-backed answers and authorised platform actions work without a provider. The optional Cloudflare Workers AI adapter uses `@cf/meta/llama-3.2-1b-instruct` as a candidate for closed-set topic classification. Every returned topic resolves to approved local content. Cloudflare receives an allowlisted public vocabulary and fixed topic codes. Names, account IDs, match records, transcripts, emails, raw free text and credentials stay within IronClad. The adapter uses standard stateless inference with AI Gateway disabled. Cloudflare documents its standard-inference retention and no-training policy, including limited safety and legal exceptions. [Cloudflare pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/) · [Model](https://developers.cloudflare.com/workers-ai/models/llama-3.2-1b-instruct/) · [Limits](https://developers.cloudflare.com/workers-ai/platform/limits/) · [Data usage](https://developers.cloudflare.com/workers-ai/platform/data-usage/)

The existing IronClad Cloudflare account is referenced by the combat highlights integration. Staging chat translation has been disabled and the translation AI settings were removed. The available Wrangler CLI had no authenticated account session, and no Ready or translation inference credential was available in the Staging project. The trial therefore starts with provider calls disabled. Free-plan eligibility, the account’s actual Neuron spend and candidate-model latency need verification on the account.

To enable a free-only trial, use the existing Cloudflare account and verify **Workers Free** and current usage in its billing and Workers AI screens. In the account, create an account-scoped token limited to Workers AI inference. Store it as a sensitive `READY_CF_AI_TOKEN` in Vercel Preview / staging and set `READY_CF_ACCOUNT_ID` for that account. Use an existing free shared Redis REST instance for the atomic counters, with `READY_REDIS_REST_URL`, `READY_REDIS_REST_TOKEN` and a separate random `READY_USAGE_HMAC_KEY` of at least 32 characters. If a verified shared store is unavailable, keep AI off. Set `READY_WORKERS_FREE_PLAN_CONFIRMED=true` only after verifying all of these conditions. Enter every credential through its provider’s secure configuration interface.

Start with the grounded representative questions in [the knowledge review](ready-knowledge.md). Trial topic classification with synthetic phrasing about match format, scheduling, map choice, replay uploads and off-topic requests. Compare exact topic accuracy, p50/p95 elapsed time, failure rate and Cloudflare-reported Neurons before retaining the candidate. Keep paid models, paid fallback and AI Gateway credits disabled. Recheck shared account usage and translation before increasing any caps.

The adapter reserves at most 2,000 Neurons and 100 attempts per UTC day across instances, with caps of 16 attempts per account and 10 per session. The account allowance described by Cloudflare is 10,000 daily Neurons. The separate Ready budget leaves headroom for other account use. Failures, timeouts and quota denials fall back to the approved answers. Budget entries expire 48 hours after the last increment of the day. User/session keys are HMACs. Operational logs contain an outcome, duration and reserved estimate without question or answer content. Vercel log retention follows the project policy. The in-process fallback request guard has one-minute counters. Cache entries are formed only for general public approved answers and expire after 15 minutes, keyed by the catalogue revision. Private replies are never shared-cached.

Before public release, propose a Privacy notice update describing optional Cloudflare inference, the exact derived inputs, operational logs, the absence of transcript retention, and applicable retention and provider terms. Submit that change through the existing legal review and publication process.
