## Access and release

Deploy from the dedicated `codex/ready-staging` worktree through the established protected `staging` Git ref. Vercel binds the development Clerk instance and the Staging Supabase project to that ref. ## Optional free inference

Source-backed answers and authorised platform actions are available without a provider. Cloudflare receives approved public rules content and bounded signals from a fixed vocabulary. Player names and identifiers, match records, transcripts, emails and raw free text stay within IronClad. Application code resolves and validates the effective rule version, source and action links. The adapter uses stateless Workers AI inference. Cloudflare documents its standard-inference retention and no-training policy, including limited safety and legal exceptions. [Cloudflare data usage](https://developers.cloudflare.com/workers-ai/platform/data-usage/)

The authenticated Cloudflare dashboard confirmed **Workers Free** as the current plan on the existing IronClad account used by combat highlights. Free includes 10,000 Neurons per account per UTC day with a provider-side hard limit. The account’s Workers AI overview did not display a numeric consumption total during the preflight. Its billing view listed R2 only, so that view cannot establish available AI headroom. A current Staging database check showed translation disabled with zero translation reservations that UTC day. The existing Vercel project had no Workers AI credential and the team’s Marketplace resource listing showed no Redis or KV store to reuse. The trial uses the existing Staging Supabase project for a shared atomic allowance once the Ready quota migration is authorized and installed. [Cloudflare pricing and usage](https://developers.cloudflare.com/workers-ai/platform/pricing/)

Cloudflare plans to retire `@cf/meta/llama-3.2-1b-instruct` on 20 November 2026. The evaluation compares `@cf/ibm-granite/granite-4.0-h-micro` and `@cf/google/gemma-4-26b-a4b-it`. The runtime model is selected after measuring answer correctness, bounded-response compliance, refusal behavior, latency and token usage. [Cloudflare retirement notice](https://developers.cloudflare.com/changelog/post/2026-11-05-planned-model-deprecations/) · [Granite model](https://developers.cloudflare.com/workers-ai/models/granite-4.0-h-micro/) · [Gemma model](https://developers.cloudflare.com/workers-ai/models/gemma-4-26b-a4b-it/)

### Secure trial setup

1. Sign in to the existing IronClad Cloudflare account. In **Compute → Workers plans**, verify that **Free** is the current plan. Open **AI → Workers AI** and verify the account’s current UTC-day consumption and other account consumers before budgeting any calls. Use the Cloudflare usage reading separately from reserved app estimates. Repeat the check after any change to account plan, usage, or translation. [Cloudflare pricing and dashboard](https://developers.cloudflare.com/workers-ai/platform/pricing/)
2. In **AI → Workers AI → REST API**, choose **Create a Workers AI API Token**. Confirm the account resource is the IronClad account only and the permission list is **Workers AI Read** and **Workers AI Edit**. Store the one-time token directly in Vercel. [Workers AI REST API setup](https://developers.cloudflare.com/workers-ai/get-started/rest-api/)
3. In the protected Vercel project’s **Settings → Environment Variables**, choose **Secret** for `READY_CF_AI_TOKEN` and a separate randomly generated `READY_USAGE_HMAC_KEY` of at least 32 characters. The environment form initially selects Production. In **Environments → Preview Branches**, select the exact `staging` branch and deselect Production under **Environments**. Confirm the scope reads only `staging` before saving. Enter credential values only in the masked field. Add `READY_CF_ACCOUNT_ID` for the verified Cloudflare account in that same branch scope. [Vercel project variables](https://vercel.com/ironclad-tournaments/ironclad-website/settings/environment-variables)
4. Verify that the Ready quota migration is present on Staging and that its reservation RPC is callable by the backend only. Set `READY_WORKERS_FREE_PLAN_CONFIRMED=true`, `READY_CF_TRIAL_UTC_DAY` to the verified UTC date in `YYYY-MM-DD` format and `READY_CF_TRIAL_NEURONS` to a positive allowance no greater than 2,000 after reserving headroom for other account use. Missing free-plan confirmation, a mismatched UTC day, an unavailable quota store and exhausted reservations keep the provider off for the request.
5. Set `READY_CF_ALLOW_EVALUATION=true` temporarily in Preview / staging to run the bounded comparison through the protected review path. Use synthetic questions with paraphrases, follow-ups, different public rule versions, unsupported requests and private-data attempts. Compare correctness against the verified passages, then compare elapsed times and provider-reported usage. Set `READY_CF_AI_MODEL` only to a candidate that passed the measured comparison and disable `READY_CF_ALLOW_EVALUATION` after testing. Paid models, AI Gateway credits and automatic retries remain disabled.

The reservation backend is shared across server instances and deployments. The app records a reservation before contacting Cloudflare so concurrent calls cannot exceed the daily app allowance. It limits requests per UTC day to 100 for the Cloudflare account, 24 per reviewer and 18 per session, and per UTC minute to 10, 5 and 4 respectively. A reservation is conservatively charged to the app quota when the provider call fails or its result is uncertain. The RPC declines a request when the translation setting is enabled, missing or invalid. Run `node scripts/ready/ai-budget-db-test.mjs` to rehearse the migration and limits on a fresh loopback PostgreSQL instance with the existing release tools.

Use server-side operational evidence to separate the public grounded response produced with Cloudflare from deterministic answers and fallback. Report Cloudflare request latency and actual reported tokens for successful requests separately from local reserved Neurons and account-level billed usage. Provider logs exclude question text, answer text and private identifiers. Cache entries are formed only for general public approved answers, keyed by the catalogue revision. Private replies are never shared-cached.

Before public release, propose a Privacy notice update describing optional Cloudflare inference, the exact derived inputs, operational logs, the absence of transcript retention, and applicable retention and provider terms. Submit that change through the existing legal review and publication process.
